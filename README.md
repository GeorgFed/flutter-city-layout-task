# Практика Flutter: список и сетка городов

За 80 минут сверстайте экран по [макету](docs/mockup.png). Данные, выбор города, переключение режима, нажатия и подсветка уже работают в оболочке. **Меняйте только четыре метода `build` с TODO в `lib/layout.dart`.** HTTP, async, Theme и собственный State писать не нужно.

## Запуск

Нужны [Flutter SDK](https://docs.flutter.dev/install) и Chrome. Проверено на Flutter 3.35.7 / Dart 3.9.2. Клонируйте репозиторий и запустите проект:

```sh
git clone https://github.com/GeorgFed/flutter-city-layout-task.git
cd flutter-city-layout-task
flutter pub get
flutter run -d chrome
```

Первый запуск покажет «Начните с TODO 1 в layout.dart» — это ожидаемый экран незаполненного шаблона. После первого получения зависимостей сеть приложению не нужна. Другие пакеты, API и аккаунты не требуются.

`r` в терминале — hot reload, `R` — hot restart, `q` — остановить. Если команда flutter не найдена, сначала завершите установку SDK и PATH; установка не входит в 80 минут практики.

Если скачали ZIP через GitHub, распакуйте его и откройте терминал в папке с `pubspec.yaml`; выполняйте команды начиная с `flutter pub get`.

## Что уже готово

- `lib/data.dart` — шесть городов с `id`, `name`, `degrees`, `description`, `icon`.
- `lib/main.dart` — приложение, выбранный город, режим списка/сетки, callbacks и рамка элемента. Текущий выбор отмечен цветом и границей.
- В AppBar есть кнопка изменения размера текста: 1× / 1.3×.
- В ваш экран передаются `header`, `controls`, `grid`, `itemCount` и `itemBuilder`. Вставьте первые два виджета в дерево; передайте последние два в список/сетку. `itemBuilder` уже создаёт нажимаемые элементы.

## Четыре TODO

| Место | Что сверстать |
|---|---|
| `CityScreen.build` | Верхний блок, кнопки режима, ниже ListView.builder/separated **или** GridView.builder с двумя колонками. Верхняя часть остаётся видна, область городов прокручивается. |
| `SelectedCity.build` | Подпись «Выбран город», полное название и температура. Длинное название переносится, не обрезается. |
| `CityListContent.build` | Иконка, название с описанием и температура справа. Название полностью видно, описание можно ограничить двумя строками. |
| `CityGridContent.build` | Иконка, название до двух строк и температура. Описание в сетке не требуется. |

Температура: `Text('${city.degrees} °C')`. В сетке разрешён `TextOverflow.ellipsis` для длинного названия: полное название видно в верхнем блоке после выбора. **У каждого элемента уже есть padding 12, фон, рамка и обработчик нажатия.** Не нужно добавлять второй обработчик или менять конструкторы.

Начните с `CityScreen`: иначе остальные компоненты пока не попадут в дерево. Затем соберите верхний блок и строку списка, после них — сетку. Точное совпадение цветов, шрифтов и размеров с картинкой не требуется; важны структура, читаемость и поведение.

## Как проверить результат

1. При ширине 320 и 800 logical px доступны все шесть городов в обоих режимах.
2. Выберите последний город с длинным названием; верхний блок показывает название целиком и `7 °C`.
3. Переключите список/сетку: выбор сохраняется.
4. Включите крупный текст кнопкой в AppBar. Нет overflow, обрезанной температуры и недоступных элементов.
5. В узком списке название не выталкивает температуру. В сетке высоты ячейки хватает на две строки названия и остальные элементы. Можно задать разумную высоту через `mainAxisExtent`, не вычисляя формулу.
6. На широком окне можно ограничить ширину всей композиции через Center + ConstrainedBox.

Проверка установки и запуска (проходит даже в незаполненном шаблоне):

```sh
flutter analyze
flutter test
```

Самопроверка готовой вёрстки:

```sh
flutter test test/layout_check.dart
```

Последняя команда **ожидаемо не проходит до выполнения TODO**. Она проверяет восемь сочетаний ширины, масштаба текста и режима, доступность последнего элемента и сохранение выбора. Автотесты не заменяют визуальный просмотр: дополнительно посмотрите отступы, переносы и читаемость на запущенном экране.

## План на 80 минут

5 минут — запуск; 15 — структура экрана и верхний блок; 20 — строка списка; 15 — сетка; 15 — граничные проверки; 10 — самопроверка и объяснение. Время ориентировочное, установка SDK — заранее.

Разрешены [примеры лекции](https://github.com/GeorgFed/flutter-widgets-examples), документация и агенты. Будьте готовы объяснить, откуда список получает конечную высоту, почему текст в Row не выходит за границы и почему смена режима не теряет выбранный город.

Результат: изменённый `layout.dart`/commit, скриншоты списка и сетки, результаты самопроверки. Срок и канал сдачи преподаватель сообщит отдельно.
